# AI 同伴：从第一次对话开始

适用于带有 **CPH AI companion / AI 同伴** 和配套运行时的 Windows 游戏包。
普通玩家无需安装 Python，也无需运行命令。当前源码是未发布的 `0.1.2.dev0 / 协议 1.2`
候选；请使用同一份包中的游戏、Mod 和运行时，旧版独立安装教程不适用于这里。

## 第一次使用

1. **启用 Mod。** 在测试世界的模组列表启用 **CPH AI companion / AI 同伴**。
   先用独立测试世界体验，保留原来的游玩存档。
2. **招募并绑定。** 让一名已招募、存活的同伴处于视野内。打开游戏的聊天菜单
   （默认 `Shift+C`），按 `Shift+I`（菜单显示大写 **I**）选择 **AI companion**，再选择
   **Bind or reconnect the fixed companion**，选中这名同伴。
   绑定的是这名角色，不是随时替换角色的槽位。
3. **配置。** 选择 **Configure AI companion**，填写服务商提供的
   **Model endpoint** 和 **Model**，在 **Set API key for this game session** 输入密钥。
   地址应为服务商提供的 OpenAI 兼容 API 根地址，不是聊天网页；模型填写准确的模型 ID。
   密钥显示为掩码，只供本次游戏进程使用；重启游戏后需重新输入。
4. **先保持简单。** 可填写简短角色背景；首次体验先保留空的
   **Allowed daily duties**，不必填写物品和配方 ID。跟随、守候基础行为仍可用；
   空列表不允许自行安排额外的到达、收集或制作，仍可接收你当面提出的请求。
   选择 **Save configuration**。
5. **主动启动。** 选择 **Start AI companion**。启用 Mod、绑定和保存配置本身不会调用模型。
   启动后查看 **Status and conversation**，确认连接状态，再选择
   **Speak to the companion** 输入一句话。

游戏内按 **h** 或选择 **Quick start（快速上手）** 可随时重看步骤；
**s / Status and conversation（状态与对话）** 显示完整状态与最近对话。
主菜单顶部只显示简短状态，每次返回主菜单时更新。**Task examples（任务示例）** 提供表达参考。
首个请求可以是：**“请跟着我，保持在附近。”** 等待回复后关闭菜单，正常走动或等待，
观察同伴是否跟随。模型返回可能需要一段真实时间；菜单中的等待不会替 NPC 推进回合。

## 怎样提出任务

每次先说清楚一个目标、数量和范围。以下是表达方式，不保证角色一定接受，
也不会跳过权限、道路、材料或危险检查。

| 想做什么 | 可以这样说 | 需要具备的条件 |
| --- | --- | --- |
| 跟随 | “请跟着我。” | 目标在可感知范围内、路线可行 |
| 守候 | “请在这里守候。” | 地点适合停留 |
| 到达 | “请去你已经看到的那处门边。” | 角色已感知目的地，不能凭空知道远处位置 |
| 收集 | “请从附近地上新捡 3 个石头，放在你自己的背包里。” | 实际可感知、允许拿取的地面物品，且有携带空间 |
| 制作 | “如果你会做简易绷带，而且材料足够，请制作 1 批。” | 说清配方名称；NPC 已知且受支持，材料和工具满足条件 |

收集时区分“**这次新捡 3 个**”与“**让你背包里总共有 3 个**”，避免数量含糊。
新增工作默认排在已有任务后；需要先处理时明确说“**先做这件事，原任务稍后继续**”。
普通闲聊不会自动取消已经接受的任务。

首批持续任务包括跟随、守候、到达、地面拾取和受检制作。收集不等于收割植物、伐木或挖矿，
也不支持通用搬运到指定容器、建造或车辆任务。部分无需交互的已知法术可经原生检查施放；
这不代表大魔法、心胜于物或 Xedra 的所有能力都受支持，不适合用作第一次体验。

## 等待、断线和进度

- **等待模型回复：** 你可以继续游戏。已经接受、仍有效的任务由本地继续执行；
  原生危险反应和基础 NPC 行为不依赖每步询问模型。断线时无法获得新的模型决策。
- **等待安全接管：** 新安排正在等待当前活动的安全边界，不等于没有收到回复。
- **受阻：** 检查路线、可见物品、工具、材料、体力和危险。条件没有变化时重复催促通常无益。
- **没有已知进度：** 普通界面只显示玩家已经观察到的进展和角色自述，不展示私有任务队列。
  角色说“会做”也不应被当作产出已经完成；检查背包和实际场景。

## 暂停、改口和停止

| 菜单操作 | 用途 |
| --- | --- |
| **Pause execution / Resume execution** | 暂停或继续本地任务执行；暂停不等于停止模型进程 |
| **Withdraw one of your requests** | 撤回你的一条指定请求，相关活动按安全规则结束 |
| **Cancel all AI work** | 取消所有 AI 工作，包括当前仍有效的任务与未开始动作；不会撤销已经产生的真实效果 |
| **Stop AI and safely return control** | 取消当前工作、停止 AI 接管并安全交回原生控制；活动可能需要等到安全边界 |

修改服务地址或模型前，先停止 AI，再配置、保存并重新启动。
不要靠删除配置、记忆或存档文件来停止任务或退还调用额度。

## 日常职责、花费和常见问题

首次跟随正常后，再按需勾选 **Allowed daily duties**。这是允许角色自主提出哪些任务的范围，
不是强制执行清单。收集和制作还受 **Allowed item IDs / Allowed recipe IDs** 限制；
这里需要内部 ID，不是中文物品名。暂时不确定 ID 时保持关闭，先使用当面请求。
**Daily duty distance** 限定自主任务范围，默认 12 格，可设为 1—60 格。
角色背景不会扩大权限，也不能免除资源消耗。

默认每次决策最多 3 次模型调用、4 次本地查询，单次请求 30 秒，整次决策 90 秒。
默认消费账户上限为 100 次调用、100000 估算 tokens；这不是每日自动重置的免费额度。
失败或取消的请求也会计入消费，读档和重启不会恢复额度。预算用尽只停止模型规划，
已经接受的本地任务和基础行动仍受原生规则管理。

| 遇到的问题 | 先做什么 |
| --- | --- |
| 没有 AI 菜单 | 核对世界是否启用本 Mod，游戏是否为配套版本 |
| 绑定列表为空 | 招募一名存活 NPC，并让其进入视野 |
| 无法启动或连接 | 停止后核对配套运行时、保存的服务地址和模型，以及本次输入的密钥；不要连续重复启动 |
| 对话没有被听到 | 回到同伴附近，确认其能够听见你 |
| 重启后要求密钥 | 正常行为；密钥不写入配置或存档，重新输入即可 |

配置与消费记录位于当前游戏用户目录的 `ai-companion/profiles/`，不需要手工管理。
更新或备份游戏时保留用户目录与存档。开发者构建和历史版本操作见
[安装说明](install.md)；具体能力与验证边界见[架构说明](architecture.md)和[验收记录](acceptance.md)。
