# CPH issue and pull-request labels

GitHub's live labels are authoritative. The inherited CCB label vocabulary below is a **triage reference**, not a claim that every label exists in CPH or that CPH Issues are enabled. Check the target repository before applying or creating a label. A label does not appoint an owner or promise a schedule.

| Purpose | Candidate vocabulary inherited from CCB |
| --- | --- |
| Type | `bug`, `enhancement`, `documentation`, `question`, `dependencies` |
| Source area | `[C++]`, `[JSON]`, `[Lua]`, `[Python]`, `EOC: Effects On Condition`, `Code: Tests`, `Code: Build`, `Code: Performance`, `Translation` |
| Triage | `duplicate`, `invalid`, `wontfix`, `help wanted`, `good first issue`, `stale` |
| Explicit hold | `<DO NOT MERGE>` with a stated removal condition |

Use the narrowest **existing** label that helps triage. Do not create near duplicates merely to preserve CCB wording. Reconcile labels through an explicit CPH review when Issues/PR triage is in use. The current feature availability is recorded in [project status](docs/project/status.md).
