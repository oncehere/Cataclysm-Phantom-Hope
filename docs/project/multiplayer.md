# CPH 双人联机

联机由主机保存共享世界，加入者通过远程玩家代理行动。两人应使用相同
CPH 版本、相同模组列表及模组内容。建议使用独立的新世界验证模组组合。
主菜单选择 Co-op 后可以主持或加入游戏；单人主菜单的默认选择保持原有行为。

## 连接与界面

Co-op 菜单主持时可以设置端口，当前菜单不提供密码设置。将可达的地址与端口
交给同伴；局域网外的连接需要双方已经可用的网络路由，游戏不建立 VPN。
需要密码时使用命令行 `--host --port <port> --password <string>`；加入者使用
`--client <host:port> --password <string>`。`--server` 尚未贯通专用无头服务器的
启动流程，应使用 Co-op 菜单或 `--host` 主持。心跳提供 RTT，短暂掉线后客户端
会尝试重连。

联机面板显示双方状态、活动进度和连接信息。`COOP_HUD_POSITION` 控制面板
位置，`COOP_PARTNER_INTENT` 控制同伴等待下一回合时的方向提示。
复制加入地址操作 `copy_join_address` 默认没有绑定按键，可在按键设置中绑定。
地址展示支持隐藏 IP；伙伴离开屏幕时的边缘提示帮助两人保持接近。

客户端可以睡眠，主机依据双方状态处理时间快进。活动完成、取消、车辆操作
和物品变化依照共享回合与主机状态同步。两人必须留在同一个模拟区域，跨维度
或远距离传送会破坏这一条件。驾驶时留意边缘警告并减速。

## Magiclysm 实验功能

Magiclysm 可以主持联机，模组说明仍标明实验性。除召唤、施法提示和生命值同步，
还接入客户端对怪物的魅惑、变形、放逐及法术状态效果；主机的怪物类型和状态
随后回传。客户端法术误伤主机时仅在主机所占的一格结算，避免重放整片范围效果。
这些路径不代表所有法术均已同步：生成物品、地形变化、角色自身的完整增益、
放逐的额外生命值成本及跨越主机模拟区域的传送仍需分别验证。长时间施法前会
提示附近敌人和施法回合数。两人须运行相同版本、模组列表和模组内容。

其他模组继续采用联机兼容说明；未测试的第三方模组显示风险提示，跨维度或
实例地图模组仍可能禁止主持。当前兼容表在 `src/mp_mod_compat.cpp`。

## 来源与维护

原始实现继承 CCB 的联机移植，其底座对应
[`79113712e446`](https://github.com/busterbogheart/Cataclysm-DDA-multi/commit/79113712e4469b931b568b388f6e1f89326e3a01)。
本轮按照用户选择的完整联机范围，从
[`5cf9a79c66ec`](https://github.com/busterbogheart/Cataclysm-DDA-multi/commit/5cf9a79c66ec82ea6d5710fb277db5ac62a71681)
适配联机净变化。保留 CPH 的 SDL3、ImGui、Lua 生命周期和单人回合结构，
未将该 fork 的 CDDA 全仓变化、品牌、捐赠入口或发布控制同步到 CPH。
原作者、许可证、来源提交及中文译文归属均保留。
完整来源和取舍见[来源清单](multiplayer-sources.md)。

`cata_test` 的 `[multiplayer]~[.],[mp]~[.]` 筛选覆盖普通适配和角色条件；
显式选择隐藏 `[network]` 条目使用真实 TCP 回环。显式目标 `cata_test-mp`
连接真实消息日志并供 `tests/project/run_mp_session_probe.py` 双进程探针使用。
回环和有限原生场景不代替 GUI、广域网、全部模组/法术或跨平台验收。

联机日志保存到所选用户数据目录下的 `mp-server.log` 或 `mp-client.log`，
可随缺陷报告提供脱敏片段。卡住时可对自己确认的 CPH 进程运行
`bash tools/project/mp-stack.sh PID`：Linux 使用已安装的 gdb 获取一次线程栈，
会短暂暂停该进程后分离；macOS 使用系统 `sample`（默认采样两秒，可追加
1—30 秒的参数）。带调试符号的构建能提供文件和行号。这个脚本要求明确 PID，
不会自动选择同时运行的其他游戏，也不会自动安装调试器。
