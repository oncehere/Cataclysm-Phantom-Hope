# CPH 工作区布局与路径边界

本页描述本机 CPH 工作区的职责，不把本机文件夹当成 GitHub 仓库内容。当前源码工作树是 `cph/`；其他 `cph-*` 是同一源码仓库的独立 Git 工作树，可能对应正在进行的任务。普通源码命令应先进入目标工作树并确认 `git rev-parse --show-toplevel`，不能在外层工作区直接执行 `git add` 或提交。

| 相对 CPH 工作区根目录 | 职责与边界 |
| --- | --- |
| `cph/` | 主源码工作树；其 `.git` 是各源码工作树共用的 Git 目录。 |
| `cph-*/` | 阶段或任务工作树；移动前须核对 Git 注册状态、未提交内容、活跃任务与绝对路径引用。 |
| `archive/worktrees/` | 已完成阶段的 Git 工作树；原 `cph-controls`、`cph-gates`、`cph-identity`、`cph-release`、`cph-sync` 路径保留兼容符号链接。 |
| `archive/evidence/` | 已封存的三次失败 E3 身份运行；原 `evidence/e3-linux-main-identity-run{,2,3}` 路径保留兼容符号链接，失败结果不改写。 |
| `inputs/` | 本机下载或保存的已核验资源、构建输入，不属于源码提交。 |
| `evidence/` | 本机命令、日志、安装试验及验证结果；历史日志里的绝对路径是当时环境记录。 |
| `build/` | 本机生成的构建目录。 |
| 外层 `.git`、`.agents/`、`.codex/` | Codex 工作区元数据；外层 `.git` 保存任务差异快照，不作为 CPH 源码仓库清理或重建。 |

在此工作区的任一已注册源码工作树，可按共用 Git 目录推导工作区位置：

```sh
CPH_WORKSPACE="$(dirname "$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")")"
printf '%s\n' "$CPH_WORKSPACE"
```

此写法用于当前“主仓库为 `$CPH_WORKSPACE/cph`”的本地布局。独立 clone、CI checkout 或主仓库迁移后应显式指定工作区和新输出目录，不要套用本机绝对路径。运行会写文件的探针时，先核对源码、构建、资源与证据目录是否互不重叠，并选择**尚不存在**的输出目录。

本地文档中形如 `evidence/...`、`inputs/...` 的引用相对于 CPH **工作区**，从源码工作树查看时分别位于工作区根目录。它们不是源码 Git 所跟踪的内容；推送 `cph/` 不会上传这些本地证据，GitHub 页面不能据此直接打开。需要共享证据时应另行选择明确的、经过核验的交付方式，并保留来源、摘要及敏感信息边界。

源码仓库内的 `docs/project/` 是 CPH 需求、决策、操作与回证导航；`project/` 是工具读取的锁定数据与策略；`tools/project/` 和 `tests/project/` 是对应实现及测试。根部 `doc/` 是继承的游戏技术文档，继续按原职责维护，不做整目录搬迁。阅读顺序见 [文档入口](../README.md)。

工作树或本地证据以后若归档，先更新位置索引与引用，再核对活跃任务和绝对路径依赖；目录移动本身不节省磁盘空间，也不能把失败记录变成通过记录。禁止扫描或改动 `obj-lua/`。
