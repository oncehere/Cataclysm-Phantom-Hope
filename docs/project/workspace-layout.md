# CPH 工作区布局与路径边界

本页描述本机 CPH 工作区的职责，不把本机文件夹当成 GitHub 仓库内容。当前源码工作树是 `cph/`；其他 `cph-*` 是同一源码仓库的独立 Git 工作树，可能对应正在进行的任务。普通源码命令应先进入目标工作树并确认 `git rev-parse --show-toplevel`，不能在外层工作区直接执行 `git add` 或提交。

| 相对 CPH 工作区根目录 | 职责与边界 |
| --- | --- |
| `cph/` | 主源码工作树；其 `.git` 是各源码工作树共用的 Git 目录。 |
| `cph-*/` | 阶段或任务工作树；移动前须核对 Git 注册状态、未提交内容、活跃任务与绝对路径引用。 |
| `archive/worktrees/` | 待核验退役或含独有内容的历史 Git 工作树；实体和兼容链接是否保留以当前索引为准。 |
| `archive/evidence/` | 已封存的三次失败 E3 身份运行；原 `evidence/e3-linux-main-identity-run{,2,3}` 路径保留兼容符号链接，失败结果不改写。 |
| `inputs/` | 本机下载或保存的已核验资源、构建输入，不属于源码提交。 |
| `evidence/` | 本机命令、日志、安装试验及验证结果；历史日志里的绝对路径是当时环境记录。 |
| `build/` | 本机生成的构建目录。 |
| 外层 `.git`、`.agents/`、`.codex/` | Codex 工作区元数据；外层 `.git` 保存任务差异快照，不作为 CPH 源码仓库清理或重建。 |

在此工作区的任一已注册源码工作树，可按共用 Git 目录推导工作区位置：

```sh
CPH_WORKSPACE="$(dirname "$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")")"
printf '%s\n' "$CPH_WORKSPACE"
```

此写法用于当前“主仓库为 `$CPH_WORKSPACE/cph`”的本地布局。独立 clone、CI checkout 或主仓库迁移后应显式指定工作区和新输出目录，不要套用本机绝对路径。运行会写文件的探针时，先核对源码、构建、资源与证据目录是否互不重叠，并选择**尚不存在**的输出目录。

本地文档中形如 `evidence/...`、`inputs/...` 的引用相对于 CPH **工作区**，从源码工作树查看时分别位于工作区根目录。它们不是源码 Git 所跟踪的内容；推送 `cph/` 不会上传这些本地证据，GitHub 页面不能据此直接打开。需要共享证据时应另行选择明确的、经过核验的交付方式，并保留来源、摘要及敏感信息边界。

源码仓库内的 `docs/project/` 是 CPH 需求、决策、操作与回证导航；`project/` 是工具读取的锁定数据与策略；`tools/project/` 和 `tests/project/` 是对应实现及测试。根部 `doc/` 是继承的游戏技术文档，继续按原职责维护，不做整目录搬迁。阅读顺序见 [文档入口](../README.md)。

工作树或本地证据以后若归档，先更新位置索引与引用，再核对活跃任务和绝对路径依赖；目录移动本身不节省磁盘空间，也不能把失败记录变成通过记录。禁止扫描或改动 `obj-lua/`。

现行工作树、分支、HEAD、未提交内容和保留理由统一在工作区外层
`WORKSPACE.md` 维护；归档日期清单只证明当时状态。主检出 `cph/` 已使用
`main`，读取主线仍须先回读精确远端 SHA，不把任意任务树的 HEAD 当作主线。

## 维护生命周期

- 独立实现用一个共用 Git 对象的工作树；开始前复用角色索引，不为阅读、状态检查或每个子步骤再建整份副本。并行子任务优先共享同一实现树的互斥文件范围。
- 每个任务结束时决定保留或退役。仍有任务、未合入提交、暂存/未暂存/未跟踪工作、嵌套仓库、锁定输入或无法确认的占用，就保留并注明原因。长时间无角色的树在下一次维护时复查，不按年龄自动删除。
- 已合入且干净的树不必永久保留实体副本。先记录 HEAD、分支、主线祖先关系、索引隐藏标志、ignored 文件与符号链接、占用和恢复命令；排除 `obj-lua/`。确认全部独有内容有归属后，使用非 force `git worktree remove`。若注册/内容/进程证据不完整则停止该对象。
- 非 force Git 移除也可能删除 ignored 文件，因此 Git 干净不是充分条件。只允许已逐项核对的可再生缓存随退役移除；输入、日志、二进制验收产物和用户文件保留。脏归档的 index/diff 不能用提交 SHA 代替。
- 本地已合入分支可用 `git branch -d` 退役。远端 head 仅在 PR 已结束且提交可达/可恢复时移除；保留 `main`、继承 `master`、`codex/sync-state` 和活跃候选。不重写历史，不增加重复标签只为替代已被 main 保留的分支。
- 旧兼容链接只有在不再服务活跃工具时才移除，清单记录原始 target。历史命令中的旧路径作为历史保留；复现时用已记录的 SHA 重建原工作树，而非在当前布局保留所有历史副本。
- 构建目录标明 source SHA、工具链和输入摘要。源码路径切换提交后，旧成功输出仍属于旧提交；使用新的隔离输出或明确重配/重建，不能借缓存文件存在报告新版本 PASS。
- 一轮维护使用一个证据目录和一份结果索引。保存原始失败、必要日志与摘要；大资源复用锁定 `inputs/`，不复制到每份证据。任何证据到期删除需另有明确清单和恢复条件。
- 当前状态只写 `status.md`，待办只写 `resume.md`，稳定操作写各主题手册。旧全文由 Git 固定版本追溯，避免在多个入口追加重复时序。生成注册表按 `ai/generated-files.yml` 更新，不手工复制清单。

## Make 构建清理

`clean` 按当前构建配置列出精确输出，完整验证计划后才删除；不按目录或
文件名前缀批量匹配。未知文件和空对象目录保留。清理需要 Git 检出，以保护
被跟踪源码；路径越界、通用输出中的符号链接、用户数据或 `obj-lua/` 会在删除前拒绝。
默认 Lua 输出 `obj-lua/` 因此不能清理，应从构建开始就使用隔离前缀。

先用相同构建参数查看计划，例如：

```sh
make clean-plan BUILD_PREFIX=maintenance- CATA_ENABLE_LUA_PLATFORM=1
```

确认输出后使用 `clean`，并保留相同的前缀、ODIR、平台、TILES 和 Lua 参数。
根目录和测试目录清理采用同一检查；仅查询计划不会创建构建目录。
`distclean` 仅处理指定发行暂存目录，保留真实存档、配置及翻译输入。

`clean` 不隐式清理语言输入。显式 `clean-lang` 只删除具备匹配 PO/MO 摘要
收据的本地生成翻译；下载的 MO、无 PO、没有收据或之后被修改的资源保留。
语言构建无法安全记录收据时仍保留编译结果，并提示清理时将保留该结果。
清理目标不是工作树、存档或外来输入的退役工具。

macOS 的 `appclean` / `dmgdistclean` 仅处理默认命名的 `Cataclysm.app`、
`Cataclysm/` 和 `Cataclysm.dmg`，要求打包完成时生成的
`*.cph-generated.json` 收据与当前内容一致。打包产物不存在时可直接首次构建；
已有旧包无收据、打包中断、未知新增或内容改动时拒绝删除，先人工检查并移出旧产物，
不要为绕过检查给未知目录补写收据。自定义 app 路径不支持自动清理。
包内相对链接只记录链接本身，DMG 暂存的 `/Applications` 链接是固定例外；
不遍历链接目标。整个清理计划通过检查后才开始删除。
这两个目标保留根 `data/` 下的用户配置与 `lang/mo` 输入。收据失败不会丢弃
成功打包的文件，但后续自动清理会保留并拒绝该无效配对。

验证在 Linux 上使用真实 Make 的临时 Git 夹具；它不证明原生 macOS 的打包、
签名或安装已经通过。`clean-plan` 和各清理目标在仅查询/清理时跳过编译探测及
对象依赖文件加载；与实际构建目标混用时仍执行正常构建规则。
