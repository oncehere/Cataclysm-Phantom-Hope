# 世界生成高级规则

本页记录世界创建菜单中的 89 个高级设置：59 个已有外部规则、25 个新增地形控制、城市规模与间距 2 个已有控件，以及 3 个气候修正。规则定义以 [`src/world_advanced_definitions.cpp`](../../src/world_advanced_definitions.cpp) 为准；本页的范围和逐项影响对应这些定义，不能当作平台测试或发布验收回证。

## 使用和继承

在创建世界的世界选项页打开“世界高级规则…”，按名称或分组筛选，选择“跟随本体／MOD”或设置自定义值，再应用更改。退出而不应用会放弃本次菜单修改。创建完成后只能查看这组规则，不能从世界设置或游戏内菜单改写；会影响内容加载和初始化的设置也因此能在开始游戏前生效。

所有条目默认跟随游戏本体和所选 MOD。菜单显示的“参考值”以及下表的参考值只是方便输入的基准，不代表当前 MOD、地区或维度实际采用的值。手动设置后，即使数值恰好等于参考值，也属于显式覆盖，优先于 MOD；重新选择“跟随”才会删除覆盖。菜单范围仅约束显式输入，不会截断 MOD 原有的取值。

城市规模和间距沿用已有 ID。只有用户明确调整相应控件或高级条目后才记录覆盖；新世界不把原来的 8／4 自动当作覆盖。旧档没有高级规则文件时继续使用地区定义，不因为旧 `worldoptions.json` 中恰好有城市数值而改变地图生成。

高风险值允许用于挑战或特殊世界。关闭城市、森林、水域或特殊地点可能让任务、开局条件和 MOD 必需地点无法满足；高密度、大范围和巨型城市可能使生成变慢。校验只能拒绝已知不合法数值或组合，不能保证每个 MOD、场景与种子都能正常游玩。

## 已有基础选项

物资、普通怪物、NPC 和成长并非都需要新开关。下列已有世界选项仍在原菜单中，此次没有复制成第二套高级配置：

| 范畴 | 已有选项 ID | 含义与限制 |
| --- | --- | --- |
| 物资 | `ITEM_SPAWNRATE` | 物品生成倍率，当前界面范围为 0.01～10；固定投放和脚本生成不保证均受影响。 |
| 怪物 | `SPAWN_DENSITY`、`MONSTER_SPEED`、`MONSTER_RESILIENCE` | 普通生成密度、速度和耐久度；改变场景难度及 MOD 怪物平衡，速度和耐久度已有重置世界提示。 |
| 怪物成长 | `EVOLUTION_INVERSE_MULTIPLIER` | 进化时间倍率，越大越慢；0 关闭普通升级途径。 |
| NPC | `NPC_SPAWNTIME` | 随机 NPC 的基准出现间隔，越大越少；0 禁止随机 NPC，不等于取消所有固定 NPC。 |
| 技能 | `SKILL_TRAINING_SPEED` | 练习和读书获得经验的倍率；0 不禁止 NPC 训练等例外。 |
| 繁殖 | `EGG_LAYING_SPEED`、`LIVE_BIRTH_SPEED` | 分别控制产卵和胎生速度。 |
| 时间和种植 | `SEASON_LENGTH`、`ETERNAL_SEASON`、`ETERNAL_TIME_OF_DAY`、`CROP_*` | 保留原有季节、昼夜、作物生长、收成及用水设置。 |

以下清单只列高级规则的 89 个条目。布尔值的“是／否”会保存成 JSON `true`／`false`；数字范围含端点，步长是菜单提示，不表示自动四舍五入。大地图区块和大地图地形格是不同尺度。

## 配置结构与加载

每个世界单独保存 `world_advanced.json`。它与已有 `worldoptions.json` 并存，只记录显式选择；不把完整 MOD 默认值复制到存档。版本 1 的形状如下，示例中的值仅说明类型和分组，并非推荐预设：

```json
{
  "version": 1,
  "external": {
    "SPAWN_ANIMAL_DENSITY": 1.5,
    "NO_NPC_FOOD": false,
    "ETERNAL_WEATHER": "normal"
  },
  "region": {
    "CITY_SIZE": 8,
    "REGION_LAKE_DEPTH": -8
  },
  "climate": {
    "WORLD_TEMPERATURE_OFFSET": -5.0,
    "WORLD_HUMIDITY_OFFSET": 0.0,
    "WORLD_WIND_MULTIPLIER": 1.0
  }
}
```

`external` 对应已有可读取的外部规则；`region` 对应地形与城市条目；`climate` 对应三个气候修正。布尔、整数、数值和文本分别保存为正确的 JSON 类型。缺少整个文件表示全部继承；已有文件中的空分组或缺少某个 ID 表示对应项继承。未知 ID、错误分组、错误类型、非有限数值和越界值会使加载失败，而不是悄悄替换成默认值。

覆盖在游戏本体和 MOD 数据加载之前激活，使物品故障、营养、载具劣化等初始化消费者能读取相同的有效设置。JSON 外部选项继续写入底层内容默认值；普通 `get_option<T>` 和 Lua `options.get`／`options.value` 读取有效覆盖。读取不会把覆盖反写到 MOD 数据。世界切换清理有效视图，快照保留该文件；恢复时重新读取规则，避免沿用另一世界或先前状态。

除单项范围外，还校验森林阈值不大于密林阈值、NPC 追赶经验下限不高于上限，以及高速公路偏移大于 0 且严格小于两向间距的一半。开始世界前还会结合已加载 MOD 的继承值复核这些关系，并确认固定天气 ID 存在。

## 维度、地区和气候边界

地形覆盖对所有维度中实际使用的对应地区组件生效，并保留各维度的地区选择与其他内容。有效地区和子组件由原定义复制，只读提供给生成器，不修改共享定义。开启某项不会为缺少组件、城市道路连接或铁路连接的地区造出默认组件；这类地区不会因为开关而被替换为地球地形。使用预生成大地图路径时，地形覆盖不替换原布局。

`DEFAULT_REGION` 保留为兼容读取器的后备字段并只读展示。它不是当前维度布局的地区选择器，不能用它切换所有维度的生物群系。地区及维度布局仍由本体与 MOD 数据决定。

温度偏移以各地区原有气候为基础，覆盖自然室外温度、地下基准、地窖温度、离线食物腐败和使用环境温度判定的水地形冻结。天气波动、地区差异和局部热源仍适用。独立的自然水体水温模型不在此次控制范围内，因此不能把环境降温理解为所有水温计算同步降低。湿度偏移在生成后钳制至 0%～100%；风速倍率只影响自然生成的风速，直接强制风速可另有结果。全部继承或显式选择 0／0／1 时，这三个修正不会额外消耗随机数。

## 没有新增的入口

此功能不提供任意 JSON 反射编辑器，也不开放没有有效读取链的选项。当前没有可用世界规则入口的游荡尸潮开关、全局降水强度倍率、独立水温偏移、任意地区或生物群系替换、任意建筑权重及 MOD 私有变量，均不作为可操作项展示。NPC 出现间隔、物品倍率等已有控件继续使用自身规则；本高级文件不会接受这些 ID 的重复副本。

中文界面由 [`lang/cph/zh_CN.po`](../../lang/cph/zh_CN.po) 维护，正常 `LOCALIZE` 构建生成独立的 `lang/mo/cph/zh_CN/LC_MESSAGES/cataclysm-dda.mo`，通过现有递归翻译加载器读取。它不合并或改写锁定的上游 MO 输入。

验证入口包括 `tests/world_advanced_*_test.cpp` 中的定向游戏测试，以及 `python3 -m unittest discover -s tests/project -p 'test_cph_translations.py'` 的翻译构建夹具。实际通过情况、平台范围和未运行项应查对应的带日期任务证据，不能从本页推断。

建筑候选耗尽时会结束该次放置，并在调试日志中按世界上下文、地区和城市大小记录一次警告，避免无限重试或逐地块刷屏。
