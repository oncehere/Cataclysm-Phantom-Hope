# 同伴任务持续执行，模型决策允许延迟

2026-10-19，用户在设计讨论中先确认 Q1—Q3，随后确认 Q4—Q7 均采用推荐方向。由于模型响应存在延迟且持续调用带来负担，同伴采用有限任务类型：模型选择目标、优先级与约束，本地任务逻辑负责持续执行，优先复用已有原生角色操作。相较于持续让模型补充具体操作，这会增加需要维护的本地任务规则，但能减少模型往返，使已接受工作在模型不可用时仍能推进。

无模型时，同伴可长期维持基础行动，并继续已接受任务直到完成、受阻或需要重新决策；受阻时保留目标并说明原因，再进入适当的基础行动。随后确认的职责范围内自主活动与意图边界见 [ADR 0002](0002-avatar-intent-and-local-autonomy.md)。首版职责配置使用 `duties.allowed_tasks`、`max_distance`、`item_types` 与 `recipes`；空资源白名单不授予自主收集或制作权限。

游戏按正常玩家操作和游戏回合推进，不为等待模型额外暂停。现实等待不产生游戏行动点；模型回复到达后仍需检查是否适用，可以晚到或因过期被弃用。

本地任务持续补充短动作队列；仅在接近需要新的高层选择、且已有信息足够时，提前请求模型。每个同伴先限制一个在途规划请求和一个候选方案，候选采用前核对目标版本、任务阶段、权限与实际资源。预取可能浪费少量请求，也不能保证及时返回；接受这个代价以减少等待空档，迟到期间继续有效任务或基础行动。

紧急反应由本地决定，在原生活动支持的最早中断点执行，保留已完成进度。恢复前重新检查目标、路线、资源和安全条件；危险暂时消失不足以证明原任务仍适用。普通生存需求在合适的行动间隙处理。

失败处理区分有限本地修复、条件暂缺导致的受阻、以及目标确定无法满足的失败。修复不得超出任务原有目标、资源、所有权和风险限制；重试前核对真实结果，避免重复交付。受阻或失败影响依赖该结果的后续工作，其他已接受且独立的任务及基础行动可继续。

模型用于玩家交流、新复杂要求、本地规则无法解决的选择，以及需要重新取舍的重要变化。任务完成能由游戏判断时直接判断；已有后续工作时不因完成而自动调用模型。同因事件合并并保留次数、累计影响及最新状态，无新信息时不无限重问相同问题。模型请求失败与游戏任务失败分别处理。

该决定已进入协议 1.2 的本地实现：持久任务补充短队列，模型候选由原生层复核；调用消费账本独立于世界检查点。用户将同伴定位为“LLM 在虚拟世界中的化身”，Q8—Q15 的自主权、第一版范围与交互原则见 ADR 0002、ADR 0003 及[完整设计草案](../project/companion-avatar-design.md)。本地测试通过范围与发行验收分开记录，见[验收契约](../../companion/docs/acceptance.md)。
