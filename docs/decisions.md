# 选型与维护面

## 复用边界

| 组件 | 实际用途 | 没有重复实现的部分 |
| --- | --- | --- |
| GNU gettext | 最终 `msgfmt --check --check-format` 验证及 MO 编译；提取由接入层 `xgettext` 或项目已有脚本负责 | 不自制 PO 语法检查器、MO 编译器、源码提取器 |
| polib 1.2.0 | 所有 PO/POT 解析、元数据、精确身份和完整 PO 输出 | 不自行解析 PO 文本，不用正则识别 PO 条目 |
| Google GenAI SDK 1.43.0 | 唯一在线补译后端，Gemini Developer API，小批量 JSON 候选 | 不使用 Gemini CLI，不维护 lokit 与 SDK 双后端 |
| 标准库 | TOML、摘要、JSON、单进程锁和可恢复文件替换 | 不引入数据库或后台调度服务 |

`msgmerge --no-fuzzy-matching` 可以同步模板，`msgcat --use-first` 可以按文件顺序选译文，但它们没有本项目要求的持续人工保护、译文摘要基线、删除恢复、历史快照来源和恢复 journal。并且 gettext 自身的匹配键不能代替本工具要求的完整三元身份。因此核心只实现这些维护策略，模板的元数据与当前注释通过 polib 组装；不用默认 fuzzy 合并去迁移变更原文。`msgfmt` 是候选发布前的最终检查门槛。

## 为什么没有采用 lokit 薄封装

先审查并动态运行固定提交 `a28493ba832ffc5506d4e45f4ddfdc5623931aa9`，没有把历史静态结论当作当前事实。它的 google provider 确实直接访问 Gemini API。上下文分组及 provider prompt 可以补充缺失语境，外层完整 PO 可以避免空上下文往返丢失；这些部分薄封装可行。

决定因素是原始模型返回经 lokit parser 后会静默复制、补齐或截断复数。模型返回一个翻译，候选可能已有三项；外层数量检查再严格也无法判断这是否伪造完整。因此仅用 CLI + 候选 PO 的薄封装不能满足严格复数验收。绕过/修改其内部响应解析和重试机制会增加一个 Go fork 与适配接口，超过小型单后端 SDK 包装的维护面。完整样例、固定源码链接、假 HTTP 实测及适合上游的独立修复建议见 [lokit 审查](lokit-audit.md)。未向上游提交或联系。

## 本工具必须承担的代码

- 翻译文本摘要与人工保护：只比较 msgstr/msgstr_plural，排除注释、排版、fuzzy 标记；删除恢复和显式解除保护。
- 精确有序来源选择：保留缺省/空 msgctxt、源文单复数；无 fuzzy 迁移；不兼容规则/无效译文分类报告。
- 历史来源：来源元数据引用原始 PO 内容摘要，快照随项目保存；上游删除后不会把保留的旧译文冒称新来源。
- 可审查候选：输入摘要、候选文件摘要、持久 journal、可拒绝覆盖的恢复；不声称多个 rename 是原子提交。
- 小范围补译：完整上下文请求、相关术语/例句、严格响应核对、缓存和未知请求状态；无业务平台或预算调度器。

## 无 API 额度时的离线交接

用户改为使用 Antigravity 自带对话模型。新增小范围文件交换 `export/responses/import`，复用 Gemini 候选的纯数据构造/校验函数、polib、GNU gettext 及现有候选/apply 协议，不增加网络服务或第二个补译后端。模型只产出 id/values，原始身份由请求 SHA256 绑定，避免反复输出长原文。外部来源明确标为 external，不误记 Gemini API 或人工保护。

`fill --cache-only` 只重新验证、复用精确匹配的历史完成记录，不发请求、不重试未知状态、不改缓存。这样旧的付费结果不浪费，人工修订仍优先保护。离线包逐批保存响应，失败可局部修复；导入时校验全批对应关系、真实输入及整个 PO，apply 再复核批次文件摘要。没有实现 Antigravity API、GUI 自动化或复杂调度器。

## 有意保守的首版限制

复数表达式只做文本规范化后的精确相等，等价公式可能产生冲突。占位符预检可能拒绝合法重排；报告并让维护者审查优于静默改写。`msgfmt` 依赖项目正确标记格式字符串。项目专用标签需要 `rules.token_patterns` 或接入层进一步检查。gettext 格式检查不判断译文含义。

polib 1.2.0 可以保留缺省/空 `msgctxt`，但无法忠实写回显式空 `msgid_plural ""`：此类输入会明确拒绝，不把其悄悄改成单数身份。这是已测试的首版兼容性限制；普通非空复数原文和多复数语言已验证。

Linux `flock` 与 fsync 协议是当前支持目标；Windows 原生需要另行实现/验证锁和文件替换语义。快照首版不自动清理。没有完成语言质量审校、费用硬封顶、数据库服务、自动下载、CI 游戏资源部署或多格式平台。
